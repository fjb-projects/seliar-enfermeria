# Compensatory period history
Implement period-based bank movements and an annual-filtered agent extract on `feat/compensatory-manual-bank`.
Delivery: feature-branch-chain; Vitest, TypeScript, build and independent high-risk verification. No real-data import or migration application authorized.

## Specs
- S1 — «Únicamente 2024 y 2025 agregaríamos el anual, y este año en curso agregaríamos el mensual. mes a mes, porque luego necesitamos el extracto para presentar». «Las vamos a agregar ... ya están depuradas ... horas disponibles menos las horas utilizadas ... para sumar al saldo disponible.» Store 2024/2025 annual net without inventing generated/taken details.
- S2 — «El valor será las horas de cada agente ya liquidadas ... horas generadas menos las tomadas si las hubo»; «Un mes puede dar negativo y se resta del banco de horas». Preserve the existing no-credit and reservation protection; negative period result alone does not imply a negative overall balance.
- S3 — «el detalle de lo que va ocurriendo ... cargamos 24 horas generadas y tomadas 12»; «filtrado ... tráeme todas las horas del 2026 detalladas». Display period, generated, taken and net when known; filter per agent and year.
- S4 — User accepted displaying consumptions already recorded by the application and permitting external taken hours, so previously processed requests are not deducted twice. Keep audited corrections, concurrency safety and retry identity. Period totals and source association require explicit review before real data changes.
